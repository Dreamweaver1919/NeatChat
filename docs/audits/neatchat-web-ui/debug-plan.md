# NeatChat Web UI Debug Plan

维护规则：本文件每次更新后必须保持 60 行以内；替换旧结论，不做无限追加。

## 目标与优先级

1. P0：输入、粘贴/上传、发送、流式响应和取消的即时反馈。
2. P0：路由切换、首屏与重进页面的可感知延迟。
3. P1：加载、空、失败、限额、删除和恢复状态是否明确且可继续操作。
4. P1：桌面/移动端布局、触控目标、键盘焦点、深浅主题和文本溢出。
5. P2：视觉一致性、信息密度、扫描效率和重复操作成本。

## 测试矩阵

- 视口：1512x805、1024x768、390x844；必要时补 320 px 宽度。
- 数据：空库、单文件、混合类型、多文件、同名文件、接近容量上限。
- 类型：文本/代码、图片/HEIC、音视频、PDF、DOC(X)、XLS(X)、PPT(X)、ZIP、未知二进制。
- 网络：正常、慢响应、断网、请求失败；确认本地操作不依赖网络。
- 输入：鼠标、触控、Tab/Shift+Tab、Enter、Escape 和粘贴。

## 执行步骤

1. 记录初始截图、DOM、控制台和关键路径时序，区分冷启动与暖态。
2. 测导航到聊天/文件库、搜索、筛选、打开/关闭预览、下载和删除。
3. 测对话选择与粘贴文件是否先展示附件，后台入库失败是否只提示不阻断发送。
4. 验证 25 MB 单文件、250 MB 总量、重复文件和并发写入边界。
5. 检查骨架屏、空状态、错误信息、按钮禁用/确认和焦点回归。
6. 在桌面与移动端截图检查网格、预览层、滚动、遮挡、溢出和 44 px 目标。
7. 对发现的问题先补回归测试，再做最小改动并复测同一场景。
8. 运行 Jest、TypeScript、Prettier、ESLint 和生产构建。
9. PDF 在 Safari 超时后验证本地原生回退；禁止 sandbox iframe、在线查看器和上传。

## 性能判据

- 暖态路由反馈目标 <500 ms；点击后 100 ms 内出现状态变化或目标页面。
- 搜索和筛选目标 <100 ms；不因 Blob 读取阻塞元数据列表。
- 列表首屏只读元数据；缩略图与预览按需读取 Blob 并及时释放对象 URL。
- 文件采集异步执行；IndexedDB 错误、容量限制或预览失败不阻塞聊天主路径。
- 结构化解析前让出主线程；压缩包先流式验证实际展开体积，异常立即二进制回退。

## 完成标准

- P0/P1 问题已修复或明确记录风险，关键路径无控制台错误。
- 桌面/移动端、空/有数据、筛选/搜索、预览/返回和焦点均有浏览器证据。
- 自动化验证通过；`audit-notes.md` 记录数据、修复与剩余限制。
- 两份审计文档与 `AGENTS.md` 均不超过 60 行。
